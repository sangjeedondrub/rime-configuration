## Project Overview

**雾凇拼音 (Rime Ice)** is a comprehensive configuration repository for the RIME input method engine. It provides a complete, production-ready input method configuration with long-term maintained dictionaries, Lua-based extensions, and support for multiple input schemes (Full Pinyin, Double Pinyin variants, Radical lookup, etc.).

This is a **configuration repository**, not a software project. The main artifacts are YAML configuration files, text-based dictionaries, and Lua scripts that extend the RIME engine's functionality.

## Repository Structure

- **cn_dicts/** - Hierarchical Chinese dictionary system with ~50MB of carefully curated vocabularies
  - `8105.dict.yaml` - Base 8,105 character set (foundation)
  - `base.dict.yaml` - Core vocabulary (17MB)
  - `ext.dict.yaml` - Extended vocabulary supplement (12MB)
  - `tencent.dict.yaml` - Large corpus from Tencent word vectors (17MB)
  - `others.dict.yaml` - Error corrections, miscellaneous entries

- **en_dicts/** - English dictionary system (~20K words + abbreviations)

- **lua/** - Rime Lua ecosystem with 27+ modules
  - Processors: `select_character.lua` (word-to-character extraction)
  - Translators: `date_translator.lua`, `lunar.lua`, `number_translator.lua`, `unicode.lua`, `calc_translator.lua`
  - Filters: `corrector.lua`, `long_word_filter.lua`, `reduce_english_filter.lua`, `pin_cand_filter.lua`, etc.
  - Advanced subsystem: `cold_word_drop/` for frequency management

- **opencc/** - Text transformation configs (Emoji conversion, Simplified ↔ Traditional)

- **build/** - Compiled binary artifacts (.prism.bin, .table.bin, .reverse.bin) generated by librime during deployment

- **default-custom/** - User customization patches loaded via symlinks

- **others/script/** - Go-based build/validation tools

- **Root level** - Schema files (.schema.yaml) and dictionaries (.dict.yaml)
  - Only 3 active schemas: `rime_ice` (main Pinyin), `radical_pinyin` (dependency), `melt_eng` (dependency)

## Build & Development Commands

### Dictionary Validation & Build

The repository includes a Go-based build tool for dictionary validation and processing:

```bash
# Navigate to build script directory
cd others/script

# Full build process (validation, auto-annotation, sorting)
go run main.go

# Sort dictionaries only
go run main.go s

# Test/temporary operations
go run main.go t          # Temporary processing
go run main.go tp         # Auto-annotate temp file
```

**Build Process Steps:**
1. Validates emoji mappings (`opencc/emoji.txt`)
2. Updates Chinese-English mixed dictionary from `others/cn_en.txt`
3. Auto-annotates missing pinyin in dictionary files
4. Adds/normalizes word frequency weights
5. Validates dictionary format (checks column count, encoding, duplicates)
6. Verifies multi-pronunciation words (polyphones)
7. Sorts and deduplicates all dictionary entries

### Dictionary Format Validation

The build tool validates three dictionary formats:
- **Type 2**: `word pinyin` (2 columns)
- **Type 3**: `word pinyin weight` (3 columns, standard format)
- **Type 4**: `word weight` (2 columns, no pinyin - used by `tencent.dict.yaml`)

### Deployment (RIME Engine)

RIME deployment compiles dictionaries into binary artifacts for high-speed lookup:

**macOS (Squirrel):**
```bash
"/Library/Input Methods/Squirrel.app/Contents/MacOS/Squirrel" --reload
```

**Linux (fcitx5):**
```bash
# Deploy configuration
fcitx5-remote -r

# Or via ibus
ibus-daemon -drx
```

After deployment, check `build/` directory for compiled `.prism.bin`, `.table.bin`, and `.reverse.bin` files.

### Wanxiang LM Update Script

For users with Wanxiang language model integration:

```bash
# Update schema files
./rime-wanxiang-update-macos.sh --engine squirrel --schema base --fuzhu base

# Update dictionaries
./rime-wanxiang-update-macos.sh --engine squirrel --dict --fuzhu base

# Update language model
./rime-wanxiang-update-macos.sh --engine squirrel --gram

# Combined update
./rime-wanxiang-update-macos.sh --engine squirrel --schema pro --fuzhu flypy --dict --gram
```

**Options:**
- `--mirror [github|cnb]` - Download source (default: github)
- `--engine [squirrel|fcitx5]` - Input method frontend
- `--schema [base|pro]` - Schema variant
- `--fuzhu [base|flypy|hanxin|moqi|tiger|wubi|zrm|shouyou]` - Auxiliary code table
- `--dict` - Update dictionaries
- `--gram` - Update language model (wanxiang-lts-zh-hans.gram)

## Configuration Architecture

### Configuration Hierarchy

RIME uses a **patch-based override system**:

1. Built-in defaults (librime)
2. `default.yaml` (global configuration)
3. Scheme-specific files (`rime_ice.schema.yaml`, etc.)
4. User patches (`*.custom.yaml` files)

### Custom Configuration Pattern

User customizations live in `default-custom/` and are symlinked to the root:

```yaml
# default.custom.yaml
patch:
  __include: rime_ice_suggestion:/    # Import preset configurations
  __patch:
    key_binder/select_first_character: "["
    key_binder/select_last_character: "]"
```

```yaml
# rime_ice.custom.yaml
patch:
  menu:
    page_size: 9
  grammar:
    language: wanxiang-lts-zh-hans    # Optional language model
  translator/contextual_suggestions: true
```

**Create symlinks:**
```bash
cd default-custom
./softlinks.sh    # Creates symlinks: *.custom.yaml → ../*.custom.yaml
```

### Dictionary Import System

Dictionary dependencies form a tree structure:

```
rime_ice.dict.yaml (main)
├── cn_dicts/8105      (characters)
├── cn_dicts/base      (core vocabulary)
├── cn_dicts/ext       (optional supplement)
├── cn_dicts/tencent   (optional large corpus - slow to compile)
└── cn_dicts/others    (corrections/misc)
```

Each `.dict.yaml` uses `import_tables` for recursive loading:

```yaml
# rime_ice.dict.yaml
name: rime_ice
version: "2024.01.01"
import_tables:
  - cn_dicts/8105
  - cn_dicts/base
  # - cn_dicts/tencent    # Commented out by default (slow compilation)
```

### Schema Structure

Each `.schema.yaml` defines an input method:

```yaml
schema:
  schema_id: rime_ice
  name: "雾凇拼音"
  dependencies: [melt_eng, radical_pinyin]

engine:
  processors:    # Input pipeline (key handling, spelling)
  segmentors:    # Text segmentation
  translators:   # Dictionary lookup & special handlers
  filters:       # Post-processing (corrections, emoji, etc.)

translator:
  dictionary: rime_ice
  enable_word_completion: true
  initial_quality: 1.2    # Priority weight vs other translators
```

**Primary Schemes:**
- `rime_ice.schema.yaml` - Full Pinyin (main, active)
- `radical_pinyin.schema.yaml` - Radical decomposition lookup (dependency)
- `melt_eng.schema.yaml` - Lightweight English input (dependency)

## Lua Extension System

### Architecture

RIME embeds Lua for extensible processing. Modules use naming conventions:
- `lua_processor@*module` - Input pipeline stage
- `lua_translator@*module` - Candidate generation
- `lua_filter@*module` - Result post-processing

The `*` prefix loads from `lua/` directory.

### Key Lua Modules

**Processors:**
- `select_character.lua` - "以词定字": Extract first/last character from words using `[` and `]`

**Translators:**
- `date_translator.lua` - Date/time generation (`rq`, `sj`, `xq`, `dt`, `ts` triggers)
- `lunar.lua` - Lunar calendar conversion (`N` + 8-digit date)
- `number_translator.lua` - Currency/number formatting (`R` + digits)
- `unicode.lua` - Unicode character input (`U` + hex code)
- `calc_translator.lua` - Simple calculator (`cC` + expression)

**Filters:**
- `corrector.lua` - Error correction & pronunciation hints (15KB mapping)
- `long_word_filter.lua` - "长词优先": Prioritize multi-character words
- `reduce_english_filter.lua` - Demote short English words in pinyin mode
- `autocap_filter.lua` - Auto-capitalize English proper nouns
- `pin_cand_filter.lua` - Pin specific words to top positions
- `v_filter.lua` - Symbol mode prioritization
- `search.lua` - Radical lookup assistant

**Advanced Subsystems:**
- `cold_word_drop/` - Frequency-based word filtering (4 modules)

### Text Processing Pipeline

```
User Input
  ↓ [Processors: key_binder, speller, lua_processor@*select_character]
  ↓ [Segmentors: abc_segmentor, affix_segmentor@radical_lookup]
  ↓ [Translators: script_translator (main), lua_translator@*, table_translator@*]
  ↓   - punct_translator (punctuation)
  ↓   - script_translator (rime_ice dictionary)
  ↓   - lua_translator@*date_translator, @*lunar, @*unicode, etc.
  ↓   - table_translator@custom_phrase (user custom, quality=99)
  ↓   - table_translator@melt_eng (English, quality=1.1)
  ↓ [Filters: corrector → autocap → pin_cand → long_word → reduce_english → emoji → uniquifier]
Candidate List
  ↓
Output
```

## Common Development Tasks

### Modifying Dictionaries

1. Edit dictionary files in `cn_dicts/` or `en_dicts/`
2. Format: `word<TAB>pinyin<TAB>weight` (3 columns, or 2 for type-4)
3. Run validation: `cd others/script && go run main.go`
4. Commit if validation passes
5. Users deploy to compile binaries

### Adding Custom Phrases

Edit `custom_phrase.txt` (highest priority, quality=99):

```
有	u	3
Amazon	amazon
有一个	ig
```

Format: `word<TAB>encoding<TAB>optional_weight`

### Creating New Lua Modules

1. Add module to `lua/` directory (e.g., `my_filter.lua`)
2. Reference in schema:
   ```yaml
   engine:
     filters:
       - lua_filter@*my_filter
   ```
3. Module must return processor/translator/filter function
4. Redeploy to activate

### Testing Schema Changes

1. Edit `.schema.yaml` file
2. Modify `.custom.yaml` for user patches (preferred)
3. Redeploy RIME
4. Check `build/` for compilation errors
5. Test in input method frontend

## CI/CD Pipeline

GitHub Actions workflow (`.github/workflows/release.yml`):

1. **Trigger**: Push to main or tag, or manual dispatch

## Word Quality & Ranking System

Candidates are ranked by weighted quality:

```
final_quality = base_weight × initial_quality + user_frequency_boost
```

**Translator Priorities:**
- `custom_phrase`: 99 (highest)
- `script_translator` (main pinyin): 1.2
- `melt_eng` (English): 1.1
- `cn_en` (mixed): 0.5
- User selection history: dynamic boost

RIME maintains `*.userdb/` for tracking selection frequency, which adapts candidate order over time.

## Important Notes

### File Encoding
- All YAML files: UTF-8 without BOM
- Dictionary files: UTF-8, tab-separated columns
- Emoji mappings: UTF-8 with emoji codepoints

### Dictionary Weight System
- Higher weight = higher priority in same-quality tier
- Weights are relative within each dictionary
- Default weight for `ext` and `tencent`: 100 (added by build script)

### Binary Artifacts
- **Never edit** `.prism.bin`, `.table.bin`, `.reverse.bin` files directly
- These are compiled by librime during deployment
- Delete build artifacts to force recompilation if corrupted

### Tencent Dictionary
- Largest corpus (~17MB) but slows deployment significantly
- Disabled by default in `rime_ice.dict.yaml` (commented out)
- Enable only if deployment speed is acceptable

### Custom Phrase Caveats
- High priority prevents word segmentation
- Use sparingly for frequently-typed shortcuts
- Not suitable for large vocabulary additions (use dictionaries instead)

- **squirrel.yaml** / **weasel.yaml** - Platform-specific UI config
- **custom_phrase.txt** - User shortcut phrases (highest priority)

## OpenCC Text Transformation

**emoji.json + emoji.txt:**
- Maps Chinese phrases to emoji (100KB+ entries)
- Example: `笑脸 → 😊`, `动物 → 🐻`

**s2t.json, s2hk.json, s2tw.json:**
- Simplified ↔ Traditional Chinese conversion
- Activated via `simplifier@traditionalize` in schema
